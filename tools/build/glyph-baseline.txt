# glyph-baseline.txt — bekannter Bestand handgezeichneter Icon-Glyphen.
#
# Erzeugt beim Härten des Gates (`tools/build-icons.mjs` /
# `tools/build/no-glyphs.mjs`), 2026-08-22. Jede Zeile ist ein Fund von
# damals: `datei:glyphe:zeileninhalt` (Inhalt getrimmt, wie ihn der Fund trägt),
# sortiert. Der Schlüssel hängt am Inhalt, nicht an der Zeilennummer: eine
# Zeile darüber einzufügen oder zu löschen macht die Baseline nicht rot.
# Der Inhalt ist auf 90 Zeichen gekürzt (bei `<svg>` auf 60). Gezählt wird je
# Schlüssel: Kommt dieselbe Zeile n-mal vor, steht sie n-mal hier; ein
# weiteres Vorkommen (kopierte Zeile) ist ein neuer Fund und lässt den Build
# rot laufen.
#
# WIE DAS GATE DIESE DATEI BENUTZT (`npm run icons:check`):
#   - Ein Fund, dessen Zeile HIER steht, wird gemeldet, aber der Build
#     bleibt grün — bekannter Rückstand, keine neue Regression.
#   - Ein Fund, dessen Zeile HIER NICHT steht, lässt den Build rot laufen.
#     Das ist der eigentliche Zweck des Gates: kein Icon darf mehr am
#     Icon-System vorbei ins Repo kommen, ohne dass es hier auffällt.
#
# WIE MAN EINE ZEILE LOSWIRD:
#   Migrieren heißt LÖSCHEN. Wird die Zeile in `js/modules/sipoc/sipoc.js` auf
#   `icon('action.delete')` umgestellt, verschwindet die Glyphe aus dem
#   Quelltext — der nächste `icons:check`-Lauf findet sie ohnehin nicht
#   mehr, aber die verwaiste Baseline-Zeile sollte man trotzdem von Hand
#   entfernen (sonst verwässert sie langsam mit toten Einträgen). Wird eine
#   Zeile stattdessen absichtlich nicht migriert (z. B. ein Marker-Icon in
#   einer Diagramm-Legende, das nie eine CSS-Maske braucht), bleibt sie
#   stehen — die Datei ist ein Bestand, keine Checkliste mit Deadline.
#
# NICHT VON HAND SORTIEREN NACH GEFÜHL — bei einer Neuerzeugung diesen
# Header behalten und den Rest durch einen frischen `icons:check`-Lauf
# ersetzen (siehe `collectFindings()`/`checkNoGlyphs()` in
# `tools/build-icons.mjs` für das exakte Key-Format).
#
